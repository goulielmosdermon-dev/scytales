Proportional type scale

The hero styles are sized off the design frame rather than set in fixed pixels. The frame is 857 wide with 798px of content between the gutters, so --u is one frame pixel expressed in our own content width. Any measurement taken off the design is written as calc(N × var(--u)) and holds its exact proportion at every viewport up to 1440 — the headline keeps its three-line break and the two columns never reflow. Below 768 the frame is too narrow to stay legible, so these fall back to fixed sizes.

03 — Foundations

Layout & Grid

Every screen is built on one rule: 2rem (32px) of padding on the left and right of every section, at every breakpoint. The design base is Standard Desktop at 1440px, so the shell caps at 1440px and the usable content width is 1376px (1440 − 2 × 2rem).

The padding rule

Content — max 1376px
2rem side padding — fixed Content container — 1376px max Viewport overflow — centres past 1440px

The one exception: detail pages

Product and solution pages run a wider gutter — --section-pad-x-wide, currently 5rem. Their copy is a single centred column, and at 2rem the display-1 headline reached the frame line. The wide value is applied by redefining --section-pad-x on .product-page / .solution-page, so every .container inside inherits it and the full-bleed rows (which offset by calc(-1 × var(--section-pad-x))) stay aligned. Nothing else on the site deviates from the 2rem rule.

Client logo belt

An uninterrupted marquee of client and partner marks, travelling left. Two identical tracks sit side by side and the belt shifts exactly one track width, so the loop has no seam. Each track uses min-width: 100cqi against the clients band (the site frame width), and space-around spreads the slack. The belt meets the orange outline — it ignores the 2rem content padding, not the viewport edge.

Because one set of marks fits inside the frame width, the belt repeats at exactly that width — so the visible band always holds one whole set and every mark is on screen at every moment. Nothing marches off and waits its turn. That fit is what the height steps below protect: the six marks' aspect ratios total ≈ 21.4, so a set measures height × 21.4 + padding, and each tier's height is the largest that still clears its own narrowest viewport.

European stars

Twelve stars turning slowly behind a section's copy, filled with falling code rather than a flat colour. One canvas draws all of it: the stars are clip paths and the rain is drawn through them, so the ring can turn while the characters keep falling straight down — rotating the whole layer instead would read as a spinning texture, not as code falling inside stars. Nothing is on screen until the section arrives; each column carries its own delay so the fill trickles in from the top.

✓ Clip the rain, don't rotate itThe stars are clip paths and the characters fall straight down through them. Turning the whole layer would spin the rain too, which reads as texture rather than as code.
✓ Arrive with the sectionThe trickle only reads as an arrival if there was nothing there first, so the layer starts at zero opacity and resets on re-entry.
✗ Don't run it off screenAn IntersectionObserver stops the loop when the section leaves. A background animation nobody can see is pure battery.

Scytále rod

Eight segments turning on the rod's own axis, with the word arriving encrypted and resolving letter by letter as each segment comes to rest. Hover a segment to throw it back into cipher. The file carries no animation — the motion lives in code, so it can be timed against scroll and replayed. Nothing about the geometry is written into the script: the axis is read off the model as whichever one the segments are spread along, and the pivots are set from each segment's own bounds, so re-exporting the model changes the result rather than breaking it.

PropertyValue
GeometryBuilt in code from the measured cross-section — no model loaded at runtime. Letters come from scytale-graph.svg's own paths.
SectionIrregular octagon, 2.5008 × 2.4314. Flats 0.9822 (top/bottom) and 1.6275 (front/back); chamfers 0.8591.
RendererThree.js r160, vendored locally in shared/vendor/ — no CDN at runtime
Segments8, each 2.0 long along the rod axis, with a 0.02 seam between them
ColourOrange faces, white edges, white letter on the front face
CipherEach letter cycles symbols until its own segment lands. Hovering a segment re-encrypts that letter.
TurnWhole facet steps (360°/8 = 45°), so a segment always lands square to camera
CameraOrthographic — the mark is drawn flat, so parallel edges stay parallel and no segment tapers with distance

✓ Read the geometry, don't restate itThe axis, the pivots and the camera distance all come from the model's own bounds. A re-export with different proportions still works.
✓ Turn in whole facet stepsAn eight-sided rod lands square every 45°. Any other angle leaves a segment resting on an edge.
✓ Keep the camera orthographicThe mark is a flat drawing. Perspective tapers the far end of the rod and turns it into a photographed object; parallel projection keeps it a mark.
✗ Don't bake the animation into the fileMotion in code can be tied to scroll, replayed and retimed. Baked keyframes can only be played.
✗ Don't light it like an objectThe mark is line art. Ambient plus one soft key keeps the faces even; a strong key turns it into a rendered prop.
✗ Don't map the letter onto the extrusionExtrudeGeometry generates wall UVs along the extrusion path, so a glyph mapped there comes out rotated and mirrored. The letter rides its own plane, whose orientation is ours to set.

Orbit states

An armillary sphere of three rings on one centre. Each ring is an ellipse whose width, height and rotation are the orthographic projection of a circle tilted in space — which is why moving between the states reads as the sphere physically turning rather than as four separate drawings. The four states below are the whole vocabulary; the live component on the Solutions pages steps through them in order, carrying its numbered tag to a new point on the sphere each time. Retune a state here and both the style guide and the site change together — the geometry lives in shared/orb.css, one custom-property set per [data-orb-state].

Only three shapes exist, and they are the same in every state: ring 1 is a circle at 100% of the box, ring 2 an ellipse of 99.7 × 40.8%, ring 3 a circle of 70.4%. Rings 1 and 2 stay centred; ring 3's centre rides a circle of radius 14.83% around the sphere's centre. Nothing resizes — only ring 2's rotation and ring 3's position change, which is why the transition reads as the sphere turning.

✓ Nothing resizesAll three shapes are fixed. Ring 2 only rotates, ring 3 only moves. The moment a ring changes size the sphere stops reading as solid.
✓ The tag stays levelIt is a sibling of the rings, never a child, so no rotation reaches it and the label is always readable.
✗ Don't rotate the groupSpinning a wrapper turns the silhouette into a wobble. Only the two inner rings change.

Fingerprint

Traced from the continuous one-line drawing: black ink is skeletonized into a centerline, sampled as thousands of points in space, then consecutive neighbors are joined with line segments to rebuild the vector.

Pipeline

  1. Threshold the source so only black ink remains
  2. Skeletonize to a 1px centerline through every stroke
  3. Place a point on every centerline sample
  4. Connect each point to its neighbor with a straight line

16 — UI Rules

Core UI Rules

✓ HeadingsAlways PP Agrandir. Tight leading (~1.0), letter-spacing −0.01em. Orange for hero/emphasis, navy for section titles.
✗ HeadingsNever set headings in SF Pro or use bold weights to fake the display face.
✓ BodySF Pro Text, 18px / 20px (body-md), ink or orange-500 for section leads. Max ~60ch line length.
✗ BodyDon’t run body text over busy imagery without a solid or scrimmed surface.
✓ ColorCream is the default canvas; navy for dark impact sections; orange reserved for action and highlight.
✗ ColorDon’t use orange for large background fills or as body text on cream (contrast/fatigue).
✓ SurfacesWhite/cream cards, 1px cream-200 borders, soft warm shadows, generous padding (32–48px).
✗ SurfacesAvoid pure-black shadows or hard 2px grey borders — keep elevation warm and quiet.

17 — Brand

European Sign

The European flag carries twelve five-pointed stars — a fixed number standing for unity and completeness. It has never tracked the number of member states, and did not change through any enlargement. Drawn here to the official geometry, in brand orange rather than the flag's gold.

Construction

  • 12 stars, evenly spaced on the hours of a clock face
  • Star centres sit on a circle of radius 1/3 of the height
  • Each star's circumscribed circle is 1/18 of the height — so the star radius is exactly 1/6 of the ring radius
  • Points face up; the pentagram's inner radius is 0.382 × the outer
  • Fill is var(--orange-500); the ring rotates counter-clockwise, one turn per 60s
